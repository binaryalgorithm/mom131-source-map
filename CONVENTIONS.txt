2. WHAT GOES WHERE
   - Tied to ONE address (a name, a type, a parameter, a formula line, a bug site) -> the TSVs above, so it shows up
     in Ghidra and in decompiled.c exactly there.
   - Spans several functions (a game rule, the save format, a subsystem) -> ORIGINAL_NOTES, citing the addresses.
   - Link both ways, never duplicate prose: an inline comment is one line + a pointer ("BUG #72", "ORIGINAL_NOTES
     GROWTH"); a document line cites seg:off.

3. CONFIDENCE (write the word into the comment; tools/coherency.py counts them every run)
   CHECKED      verified instruction by instruction in the assembly (tools/dis16.py) or by an executable check
   READ         (default when no word is written) from reading the decompile; plausible, not proven
   PROVISIONAL  best guess; needs a second look - write what is unsure
   GAME         confirmed in the running game (Chris, or the harness tools/harness/ reading the live RAM)
   CORRECTION: was <old>   prefix when a name / field changes meaning (keeps the history visible)
   Bugs use the same words plus READ+asm (reader checked asm), WIKI (community wiki only), OPEN (we disagree with
   the community). Everything READ / PROVISIONAL is a revisit list for phase 2.
   Answer keys (community wiki, Unofficial Patch notes via re/patch_map.tsv, later ReMoM) are used only AFTER our own
   reading; a match is marked COMMUNITY-KNOWN (<source>), never copied in as our claim.

4. NAMING STYLE
   Functions: Area_Verb_Object (City_Growth_Rate, Diplo_Make_Peace); Screen_* = screen with its own input loop;
   *_Redraw = redraw callback; *_Load = asset loader; AI_* = AI decisions; Help_Load_* = help-list loaders.
   Auto names Mod_seg_off (e.g. Combat_8f51_0347) mean "not analysed yet".
   Globals: lower_snake (p_ prefix for far pointers: p_cities); config_* = MAGIC.SET options.
   Comment start "(a, b, c): ..." = the parameter list (feeds param_names.py: plain identifiers only, "_" = unknown).

6. EXECUTABLE CHECKS (strongest evidence for behaviour)

8. PHASE-2 READING RULES (learned step 48-49)
   - Ghidra DROPS some zero stores in big functions (ai_stack_count = 0 at ebda:2dae, loop counters reset to 0,
     sums cleared to 0 - seen in e318:09e5, ebda:0302, ebda:2da6). A variable that "looks uninitialised" or a loop
     that "looks dead" must be checked in the asm (tools/dis16.py) before it becomes a bug claim.
   - Ghidra labels single ELEMENTS of a table as separate globals (DAT_3f33_4af8 = ai_category_weights[1]); work out
     the table base before judging an index as off by one.
   - Read control flow (break / continue / return) in re/current_WIZARDS/decompiled.c or the asm, not a filtered view
     (tools/peek.py hid those keywords until step 48).
   - Community patch bytes: tools/patch_show.py NAME (file format = offset line, then OLD byte, NEW byte). A 151-set
     fix can target a bug an earlier community patch introduced - check the 1.31 bytes first.
   - tools/dis16.py disassembles only 0x400 bytes from the start address - for a long function start a second run
     further in before concluding an instruction is absent (step 50).
   - Diplomacy rows: in human-AI diplomacy the AI's attitude lives in wizards[0].X[AI] (relation mirrored; bias and the
     three interests are not). Diplomacy_Relation_Change's observer is never the human. Several AI routines read
     wizards[0] (the human's row) where the other wizard was meant - check which row before describing a rule.
