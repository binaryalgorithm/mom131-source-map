MASTER OF MAGIC v1.31 - UI INPUT MAP (per screen: every control, its box, its key)
Built 2026-10-26 from the byte-identical source rebuild (WIZARDS.EXE / MAGIC.EXE recompile to the GOG 1.31 bytes) and from
live control tables read out of the running game. Coordinates are VGA mode-13h pixels, 320 x 200.

HOW THE GAME READS INPUT (UI library, src/wizards/UI.C - one library in both programs)
  * Each screen fills one control table and then waits in a loop. Entry 0 is a null control.
  * A click returns the LOWEST-numbered control whose box holds the mouse position (+ the pointer's hotspot offset,
    0 in every pointer region captured). Box bounds are INCLUSIVE on all four sides: x1 <= x <= x2, y1 <= y <= y2.
  * Overlapping boxes are normal (a full-screen 'click anywhere' region after the buttons; a dialog area region
    after its buttons): order decides.
  * Key-only controls sit off screen at (500,500). Keys are matched to a control's hotkey (letters upper-cased).
    Game key codes: arrows (grey or keypad) Left/Right/Up/Down; keypad 7/9/1/3 are separate keys (diagonal moves);
    F1-F10; Enter, Esc, Tab, Backspace, PgUp/PgDn/Home/End/Ins/Del. 'Alt+R+V+L' = hold Alt and type R, V, L.
  * Control types: button / toggle / latch = picture buttons (box = picture size); picture = picture hotspot;
    region = plain rectangle (or key-only); value_region = rectangle that returns a value; grid = cols x rows cells
    (the hit cell = (x - x1) / cell_w, (y - y1) / cell_h); slider (value from the mouse position along the box);
    text_button = list line (a disabled one does nothing); text_input / text_line = editable text (Enter accepts).
  * Right-click help is a separate list of (help id, box); help titles below are the game's own (HELP.LBX), shown
    only as a label for the control they cover. The control's own 'help' word is never read by the game.

PART A - STATIC: every UI_Add_* call of both programs (365 call sites in 97 functions; 274 resolve to an exact box or
  are key-only, 2 need the font height, 89 are computed at run time and show their formula). Rows are in source
  order = the order the controls are added (= index order) when every call runs. 'if' = added only on some paths,
  'loop' = added once per iteration (expanded when the bounds are constant: one row per index).
  Name = the source variable that keeps the control id (the screen code compares the returned id with it).
PART B - LIVE: 26 screens captured from the running game (index, type, box, key, help title, static name).
  Cross-check: TOTAL: 287 live on-screen controls, 155 (54%) reproduced exactly by the static reading
