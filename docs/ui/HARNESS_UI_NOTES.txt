HARNESS UI NOTES - Master of Magic 1.31 as driven by the project's test harness (2026-10-17 .. 10-23)
How a script can play the game in DOSBox-X: keys, clicks, which screen is up, where the state is. Only what was USED and
SEEN to work is listed. The bracketed tags name the harness check or test that verified a line; the harness itself is
not published. Coordinates are DOS pixels (320x200); the harness took screenshots at 2x (640x400). The complete
per-screen control tables are in UI_INPUT_MAP.txt beside this file.

HOW INPUT REACHES THE GAME
  keys    PostMessage WM_KEYDOWN / WM_KEYUP to the DOSBox-X window (works even when the window is on a hidden
          desktop).
          Grey arrows / Home / End / PgUp / PgDn are sent extended (E0); 'kp1'..'kp9' are the keypad keys with NumLock
          off (no E0). The game tells them apart: Key_Read_Translated (2579:03fb) maps E0 Home/End/PgUp/PgDn to codes
          5-8 and the keypad ones to 0x1a / 0x1c / 0x19 / 0x1d; arrows (either kind) to 1-4.  [check_203: grey Home /
          End did nothing on the map, kp7 / kp1 moved the stack]
  mouse   write the game's own mouse latch through DOSBox-X's Game Link shared memory (posted mouse moves do not
          work on a hidden desktop). WIZARDS.EXE latch DS 0x78c2.. ; MAGIC.EXE latch DS 0x4394.. (same library code, found by byte
          match).  [every click below]
  RAM     read through Game Link as well; DGROUP is found by the 'Run INSTALL' string + a second
          program-specific string (both EXEs carry the first one).

GAME STATE (DGROUP offsets, live)
  game_turn 0xbd90   num_units 0xbd92   p_units far 0x9ec2 (0x20 per unit)   p_cities far 0x9cbc (0x72 per city)
  p_terrain_maps far 0x9cdc (2 x 0x12c0)   map_view x / y / plane 0xbd8a / 0xbd88 / 0xbd86   wizards 0x9eca (0x4c8)

GAME KEY CODES (from the asm of Key_Read_Translated 2579:03fb - what each BIOS key becomes inside the game)
  Esc 0x1B | Backspace 0x0B | Enter / keypad Enter 0x0C | Tab 0x0D | F1-F10 0x0E-0x17 | F11 0x91 | F12 0x92
  grey (E0) arrows: Left 1, Right 2, Up 3, Down 4; PgUp 5, PgDn 6, Home 7, End 8, Ins 9, Del 0x0A
  keypad (no E0): 4 -> 1, 6 -> 2, 8 -> 3, 2 -> 4, 7 -> 0x1A, 9 -> 0x19, 1 -> 0x1C, 3 -> 0x1D, 5 -> 0x1E, + -> '+', - -> '-'
  Ctrl+Right 0x80, Ctrl+Left 0x81, Ctrl+Up 0x82, Ctrl+Down 0x83, Ctrl+Home 0x84, Ctrl+PgUp 0x85, Ctrl+End 0x86,
  Ctrl+PgDn 0x87, Ctrl+S 0x90; Alt+A..Alt+Z 0xA0..0xB9 (Alt hotkeys = letter + 0x5F); Shift+8 ('*') is swallowed (0)
  everything else: the BIOS ASCII byte. Dev keys (inert in release): F11 memory report, F12 SCRDMPnn.FLI screenshot,
  backquote / tilde toggle DS:828a / 828c.
MOUSE: driver range x 0..638 (halved -> 0..319), y 0..199; event handler 2579:02bc draws the cursor itself (saves /
  restores the VGA registers) and feeds the click latch read by the UI loop (the latch the harness writes).

PER-SCREEN CONTROL TABLES (2026-10-21): the harness dumped the live control table of each waiting screen (boxes, keys,
  help titles) - screens/<program>/<name>.json beside this file; the 'route' note is the input that led there from the
  previous screen (k:KEY, a:LETTER = Alt+letter, c:X,Y = click, r:X,Y = right click, w:SECONDS = wait, map: = Esc until
  the overland map). Full map: UI_INPUT_MAP.txt (static + live, cross-checked). Esc from Items returns to Armies.
