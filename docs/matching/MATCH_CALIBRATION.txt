MATCH CALIBRATION LOG - what byte-matching proved about our annotations (step 78c-T onward)
=============================================================================================
Byte-matching a module with Borland C++ 3.1 (BCC -c -mm) checks every type, signedness, array shape and expression we
wrote: a wrong one changes the compiled bytes. Each row: what we had, what the match proved, the evidence, the module.
Kinds: TYPE (struct field / global / local type), SHAPE (array / pointer shape), FORM (how the source was written -
changes the decompile's readable form only), NAME / LOGIC (our reading was wrong), CONFIRMED (a provisional reading
proved right).
TWO CHECKS, both needed (adversarial review 2026-10-19): tools/match_module.py compares every byte the compiler fixes;
it MASKS the bytes the linker fills in, so on its own it cannot tell which global or which function an instruction
refers to. tools/match_fixups.py checks those: every data reference against the source's '/* DS:xxxx */' address,
every call against functions.tsv (linear address; overlay stubs accepted), every string literal against the game's
text. Negative test: swapping vis_bitmap_arcanus / vis_bitmap_myrror in Visibility_Clear still byte-'MATCH'es and
is caught by the fixup check (2 WRONG). tools/match_build.py runs both. A module counts as matched only with both.
