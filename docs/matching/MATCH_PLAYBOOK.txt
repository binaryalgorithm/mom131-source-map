MATCH PLAYBOOK - distilled working rules for byte-matching a module (written 2026-10-19 after batch 24)
Read this BEFORE starting a module. Details / evidence per rule: MATCH_CALIBRATION.txt (batch numbers in brackets).

=== WORKFLOW (per module) ===
1. Prep: python tools/match_prep.py WIZARDS <seg> work/bcc/prep/<seg>.asm.txt   (asm + decompile)
         python tools/match_prep.py WIZARDS <seg> --decomp                      (decompile + externs list)
   Also dump the module's DGROUP data (python one-liner on work/flat/WIZARDS_FLAT.EXE, base hdr + 0x26aa*16) and
   find where it starts / ends: the previous module's last data item and the next module's first.
2. Read the asm in chunks; filter noise (grep -v pop cx / push ax) and print several instructions per line - the
   decompile is a hint only (it invents ?:, merges branches, mislabels arrays, garbles long math).
3. Write src/wizards/<FILE>.C (big repetitive bodies: generate with a scratch Python script, via the Write tool -
   bash heredocs break on quotes / backslashes; for a literal backslash in a python -c use chr(92)).
4. python -P tools/match_build.py WIZARDS <seg> src/wizards/<FILE>.C   (grep ^MATCH|^DIFF|segment|fixups|^Error)
   Diff: python tools/match_diff.py WIZARDS <seg> work/bcc/m/<FILE>.OBJ <Function>   (lcall vs push cs/call lines
   are normal - TLINK rewrites)
   Byte-level: compare img[base+off] with the OBJ _TEXT bytes (omf_match.modules) when the diff shows nothing.
5. 100% bytes -> add to src/wizards/MODULES.TSV and src/magic/MODULES.TSV (../wizards/FILE), then
   python -I tools/source_names.py --apply ; rerun match_build (WRONG name lines vanish) ;
   python -P tools/match_build.py MAGIC <magicseg> ... ; python -P tools/match_names.py MAGIC --apply ;
   rename MAGIC labels the shared source disproves (magic_data_names_hand.tsv + _all);
   both regressions: python -P tools/match_all.py WIZARDS / MAGIC (run in background, ~2 min each);
   log MATCH_CALIBRATION.txt, bugs to BUGS_AND_QUIRKS.txt, commit.
5b. MAGIC-only modules (src/magic/X.C): python -I tools/magic_source_names.py --apply (names -> magic_data_names_hand;
   0 conflicts), python -P tools/match_all.py MAGIC. [32]
6. Record progress: module, size, % completed for both programs.

=== COMPILER RULES THAT KEEP COMING UP (BCC 3.1 -mm -a -d) ===
Registers
 - Auto allocation (no 'register'): by use count; ties go to the EARLIER declared variable. [19, 22, 23, 25]
 - Explicit 'register' overrides use counts: SI then DI in declaration order; explicit LOCALS take registers
   before explicit PARAMS. Mix one explicit + auto when the order needs it. [7, 19, 20, 23, 24]
 - An UNUSED local takes no stack slot either. A frame slot no instruction touches = a local only mentioned in a
   statement without code ('x;'). [26]
 - Register variables take no stack slot: move their declaration freely to fix the order (stack layout of the
   others is unchanged). Stack slots: first declared = [bp-2]; char arrays word-aligned; a char local sits odd.
 - Stack layout: locals of <= 10 bytes get slots first (declaration order from bp-2 down), locals of >= 12 bytes
   (arrays, structs) go below all of them, in declaration order. Test layouts with BCC -S (scratch bccS.py). [34]
 - A register variable in CX where the game has SI / DI: BCC saw a leaf function - a call is missing. [34]
 - Leaf functions may put register vars in CX, DX, AX, BX too. [19, 21, 22]
 - With inline asm (push es ... pop es through a far pointer is a sign): register LOCALS take SI before register
   PARAMS - copy the param into a register local when the param must be SI. [31]
 - A far pointer param that is patched in place ('mov ax, ds / mov [bp+N+2], ax'): 'int far *p' +
   '_AX = _DS; *((unsigned *)&p + 1) = _AX;' (_DS alone stores DS directly). [31]
 - Functions with inline asm get NO automatic registers; 'asm mov si, x' makes BCC save SI. [8]
 - A parameter BCC keeps in SI/DI is loaded at entry ('mov si, [bp+N]').
Branches / layout
 - if/else of two calls with the same tail is CROSS-JUMPED: each branch pushes its own argument, then jumps into
   the shared push/call (looks like ?: in the decompile; a real ?: computes into AX and pushes once). [20, 24]
 - 'if (c) return 1; return 0;' -> second 'jmp exit' cross-jumped onto the first. [19]
 - The branch order shows the written test: 'if (a != -1) {X} else {Y}' puts X first. [21]
 - 'default: break;' (last) = the dispatch's no-match lands on a lone 'jmp end'. It changes the tail-merge targets:
   when merges look wrong, try it and the case order in the variants harness (scratch variants.py + vfuncs.py). [31]
 - Two identical tails NOT merged = a different nesting: 'if (a) F(); else { G(); F(); }' cross-jumps the then-F
   into the else-F; 'if (!a) G(); F();' has one F. [31]
 - 'for (c++; cond; c++)' enters the loop by a jmp onto the increment (init cross-jumped). [31]
 - for/while loops: jmp to the test at the bottom; a 'for (x = e; ...; ..., x = e)' init is cross-jumped onto
   the increment copy (bare jmp into the assignment). '(x = e) != 0' tests AX; a separate assignment tests
   memory; a comma expression in a condition materialises 0/1. [21]
 - Switches: >= 4 cases -> jump table after the function (aligned from the module start, -a); fewer -> cmp chain.
   Case bodies in source order; the table order reveals it.
 - TAIL MERGING is the codegen's own (also with -O-) and not local: alone, a switch merges only its LAST case into
   the first case's identical tail; if any switch in the function ends its cases with a '?:' expression, EVERY
   identical case-tail pair in the function gets merged. Extra merges in your build = some '?:' tail that the
   original wrote as 'if (c) v = A(x1); else v = A(x2);' (same bytes after the if/else cross-jump). Test shapes with
   a small synthetic file before editing a 4 KB function (scratch synth.py / merges.py). [25]
Calls / prototypes
 - Many functions have NO prototype in the original: different argument counts at different calls (LBX_Error 3/4,
   Font_Select 2/3, Font_Select_Shadow 3/4, EMS_Named_Handle 2/3, Print_Text_Right 3/4). Do not include GAME.H
   in such modules; declare locally; '#pragma warn -pro' keeps BCC under its warning limit. [18-24]
 - A function returning long MUST be prototyped where used (else 'cwd'): DOS_File_Size, Random_Get_Seed. [24]
 - Check the module map's "partial" verdicts first: compare the two segments byte for byte (only 1-2 byte address
   runs differ = the same source; Sound was one - Ghidra had missed a function). [26]
 - Calls to functions defined EARLIER = 'push cs; call' (4 bytes); later = far call TLINK turns into
   'nop; push cs; call'. The nop tells you the definition order.
 - A non-void function ending in a call with no return returns AX of that call. [8, 24]
 - Long constants pushed as 'xor ax,ax / mov dx,K / push ax / push dx'; a zero offset written as '0, 0' (two int
   args) pushes three separate zeros. [23]
Expressions
 - x - K compiles as 'add ax, -K' for int x, 'sub ax, K' for unsigned x. Unsigned division (div) means an unsigned operand (find which). [16-24]
 - 2-D far array param 'T (far *p)[60]': les bx / add row*60 / add col; flat p[y*60+x] adds the index first. [22]
 - 2-D struct MEMBER 'char a[6][40]': s[i].a[r*40 + k] and s[i].a[r][k] compile the same; a constant on the column
   tells them apart - only a[r][k + 10] gives base + r*40, + k, disp +10 (the flat form adds k to r*40 first). [33]
 - Long variables: 'x = x | K' loads DX:AX and stores back, 'x |= K' works in memory (as for ints). [33]
 - Finding a MAGIC module's data block: scan code refs per DS range (scratch mdsref.py); a block ends where the
   next module's refs begin. Immediates like 'mov ax, 3840h' (sizes) are false hits. [33]
 - '(long)a * b': the LEFT operand goes to CX:BX (evaluated first), a constant goes last. [24, 31]
 - 'v = _DS' is 'mov [v], ds'; the game's 'mov ax, ds / mov v, ax' is inline asm (and 'seg'/'offset' are asm
   keywords - never C names used in asm). [7, 23]
 - xor r,r: BCC codegen 33 /r, inline asm 31 /r - tells C from asm. [19]
 - A char compared with a code >= 80h is written '' (byte cmp; in a switch 'cmp ax, 0FF91h'). [31]
 - Misplaced parentheses in the original are real: 'Heap_Block_Valid(block == 0)'. [23]
 - A long quotient truncated to int mid-expression shows as 'cwd' after LDIV@ (or imul instead of LXMUL@): the
   original has an int cast there, '(int)(L / d) / (long)e'. [25]
 - 'x = x & K' (via AX) and 'x &= K' (direct on the register) compile differently. [25]
Data
 - Local-array initialisers: char arrays byte-packed, int arrays word-aligned (a pad byte before = int[]). [34]
 - Module data = its initialised globals in definition order, local-array initialisers, then literals in first-
   use order; -d merges identical literals and tails ("" lands in another literal's NUL). Odd-looking bytes are
   real source ("YO MOMA\0\0", "  "). The match_fixups 'data block' check compares all of it. [14, 20, 23, 24]
 - Uninitialised globals = BSS: declare extern (definitions settle at the link milestone).
 - A local struct copy's size shows in the frame layout: LbxPicHeader is 18 bytes, not the 16 the code copies. [25]
 - source_names.py reads 'extern ... /* DS:xxxx */' and initialised definitions whose DS comment follows the ';'.
Names
 - BCC keeps 32 characters of an identifier: rename longer database names when their module is matched
   (names.tsv, names_all, magic_names(_all), both current functions.tsv). Still over 32: 4 names (grep). [21, 24]
 - Our names are ours: rename when the matched code shows they are wrong, note "renamed from" in names.tsv.

=== META OBSERVATIONS ===
 - First compile now matches 70-90% of functions; the time goes into READING asm, not fixing. Read big regular
   functions as "one block x N copies" and generate them.
 - Each module still shows 1-2 new patterns; log them here and in MATCH_CALIBRATION.
 - The original code is copy-paste heavy (redraw twins, loaders in 3 variants, 8 branch copies): bugs live in the
   copies that were edited by hand (#339, #387, #391). Compare the copies when reading.
 - Matching corrects the database: wrong comments (Beep, Paragraph_Layout_Lines), a wrong bug (#207), wrong
   MAGIC names. Record every correction.
 - Never run match_build while match_all runs: both use work/bcc/m (a build deletes the regression's files).
 - Context budget: a 12 KB module costs a lot of reading; prefer finishing a module before a compact and keep
   STATUS "RESUME HERE" current after each commit.
 - Jump-table pad (-a) parity is decided BEFORE jump sizing, from BCC's first-guess counter [35]: a conditional
   jump is first counted short (2) and grows to 'jcc +3 / jmp near' (5); a goto / else jump is first counted
   near (3) and may shrink to 2; a reused register ('mov bx, ax' for a variable just loaded) is first counted as
   the load. So 'if (c) { > 127 bytes }' and 'if (!c) goto L;' give the SAME bytes but opposite pads. If every
   instruction matches and only a table pad is off: compile the function alone (scratch wg_keep.py + bccC.py),
   read the drift parity, and try the goto / structured spelling of each long forward branch. The drift is per
   function (earlier functions do not carry it); equivalent spellings (x++ / x += 1, != 0, ...) never change it.
 - Cross-jumping [35]: BCC replaces a statement tail identical to another one (earlier OR later in the function)
   with 'jmp' to it - identical case bodies, repeated 'return 1;', the 'x--; y--; break;' tails. Write every case /
   return out in full in code order; never merge them into one case label to 'explain' the jump.
 - Functions that return a value only on some paths are 'int' (Place_Neutral_Cities, Progress_Bar, Unit_Create).
 - Reading big generated code: scratch tcollapse.py (T[y+a][x+b] for p_terrain_maps) and ccollapse.py (C[i].field
   for p_cities) fold the address arithmetic of a compact listing.
 - LINK (batch 36): tools/link_magic.py + work/link/exe_cmp.py rebuild MAGIC.EXE byte-identical. A module's globals
   must be DEFINED in the module that owns them (its data / BSS block); extern-only sources match module by module but
   do not link. Initialised data: the block owner (wiz_neighbours.py checks both programs); BSS: reverse declaration
   order. Overlay modules: compile with -Y, and keep their prototypes in the stub thunk order (proto_order.py).

LIST D LESSONS (batches 53-72, 2026-10-20) - evidence in PROCESS_LOG.txt under each batch number
Registers / locals
 - Stack slots: the FIRST declared non-register local gets bp-2 (arrays by their start: char a[6] first -> bp-6);
   register variables take no slot, so they may be declared anywhere. Read the frame first, then order declarations.
 - SI / DI choice is weighted (loop uses count more), not a plain use count. Recipes that worked: declare the
   variable that must win the register BEFORE its rival (ties go to the earlier declaration) [66 70 71]; an explicit
   'register' local outranks a register param [70]; when two explicit registers come out swapped, make only ONE of
   them 'register' and leave the other an auto declared early [67]; leaf functions also use CX [56 71].
Control flow
 - Empty statement forms: 'if (c) { } else { }' -> jne X / jmp X [66]; an empty-bodied 'while (e) ;' -> jmp test /
   test: ... / je test (a jmp to the next instruction) - not a do-while [67]; a lone 'if (c) {}' keeps only the jcc.
 - Cross-jump scope: an inner if/else pair of identical calls is merged (mov ax,A / jmp / mov ax,B / push ax ...),
   but NOT with an outer branch's identical call; a ternary inside one call DOES merge with that outer call. When the
   game shows two separate full calls, write nested if/else with full calls, never a ternary [65 70 80d6].
 - Switch: case bodies are laid out in SOURCE order, the compare chain / table is sorted by value [69]; several
   'case a: case b:' to one body, and 'case 1: default:' sharing a body, show as 'cmp ax,1 / je L / jmp L' [55bb];
   'switch (x) { case 0: case 1: case 2: ...}' gives 'mov ax,[x] / or ax,ax / je / cmp ax,1 ...' where an || chain
   compares memory [69]. Writing every case out in full lets BCC cross-jump them into the game's shared tails - no
   gotos needed (Diplo_Load_Message's 21 cases) [69].
 - A function ending in 'f();' (no return) returns f's AX; a final 'return f();' after an earlier 'return 0;' adds a
   jmp to the epilogue [68]. Int functions without a final return are common (AI_Hire_Hero, Fog_Smooth).
 - Jump-table pad: fix every size difference first - a pad mismatch was twice only a knock-on [72]; otherwise try
   another spelling of the condition before the table (nested ifs instead of one && gave the pad) [71].
Expressions
 - 'c - x' with x in memory compiles mov ax,c / sub ax,x; the game's mov ax,x / neg ax / add ax,c is '-x + c' [72].
 - 'x = x + n' (load / op / store) vs 'x += n' (op on memory) and 'x++' (inc word ptr) are distinct [all].
 - Long values: BCC spills a long as mov ax,[hi] / mov dx,[lo] / push / push ... pop / or; long & const tests are
   word pairs (and dx,lo / and ax,hi / or dx,ax). Two 16-bit struct halves read this way are ONE u32 [71].
 - Without <string.h> strlen is int: 'i < strlen(s)' is a signed jg [70]. Comparison constants fix the spelling:
   cmp 22 / jg = '<= 34', cmp 0 / jl = '>= 0', cmp 1 / jle = '<= 1' or '> 1' by branch layout [67 71 72].
Prototypes / calls
 - When a module calls a function with a different argument count than elsewhere, the original had no prototype in
   scope: move that prototype out of GAME.H into the sources that use it (tools: tools/moveproto.py) and declare it
   unprototyped in the odd module (Print_Text_Centered [67], Font_Select / Font_Select_Shadow [69], Fill_Box_Styled
   [71], far_strcpy [58], Near_Alloc_Release [65]). Return types too: Screen_Turn_Report is int [72].
 - A forward call (callee defined later in the same segment) is a far call that TLINK turns into nop / push cs /
   call; a call to an earlier function is push cs / call from the compiler [66].
 - BCC keeps 32 characters: rename longer database names (names.tsv, names_all, functions.tsv) [69].
 - Declaration drift (read-only, < 1 s): python -I tools/declcheck.py -> work/reports/DECL_CONFLICTS.txt. Parses
   every .C in both MODULES.TSV + GAME.H and lists, per symbol with file:line: 1 extern / definition type clashes,
   2 prototypes differing between files (also vs a TASM PROC's argument words), 3 call sites whose argument count
   disagrees with the callee's definition (or its prototypes), 4 documented odd-arity (an unprototyped 'f();' or an
   implicit call with a comment saying why - NOT errors), 5 unprototyped 'f();' with no comment, 6 DS:xxxx clashes.
   Run it after adding a module: a NEW entry naming the module is drift to fix now or to log for P1. When a module
   deliberately calls without a prototype, put the reason in a comment beside 'f();' (or naming f with the word
   'prototype' in the file header for an implicit call) so it lands in section 4.
Data / names
 - '-d' merges a string into the TAIL of an earlier literal ("" into "HIRE"'s NUL, " in " into "Plague in ", "P"
   into "MP") [65 72]; dump the literal block first (python tools/dstr.py LO HI).
 - Initialised module data (counters = 0, color tables) is DEFINED with its initialiser; its DS comment must follow
   the closing ';' and stay on ONE line, or tools/source_names.py skips it [68 70].
 - Unreferenced BSS between two matched modules (c094, c124) must be given an owner for the stand-in builder:
   declared last in the later module, PROVISIONAL [66 68]. Variables used only by other modules but inside this
   module's BSS block are defined here (combat_result_min_lines) [72].
 - A table indexed [x][i - 1] for i = 1.. shows as [bx + base-1]: the real start is one higher [70].
 - Signedness retypes this run (all from CBW loads, checked against every decompile reader first): Wizard
   war_request_target / pending_msg_city, BattleUnit.owner, p_exploration_maps unsigned char; next: Unit.damage i8.

LIST D LESSONS (batches 73-77, 2026-10-20) - evidence in PROCESS_LOG.txt under each batch
 - 'if (c) continue;' is jcc-over + jmp to the increment (never a single jcc); an inverted if with an empty /
   continue branch explains a 'jne X / jmp Y' pair that a short jcc could have reached [77].
 - Jump-table pad: with identical code bytes, the statement shape before the switch decides it - an early
   'if (x) return;' gave a pad byte the game lacks; 'if (!x) { ... switch ... }' removed it [77].
 - Cross-jump: to get the game's 'A; jmp L / B; L: tail' with the tail NOT merged into a sibling branch, write the
   tail statement inside BOTH inner branches (BCC merges that inner pair) instead of once after the if/else [76].
 - 'if (a == b) return 1; else return 0;' gives mov ax,1 / jmp / jmp / xor ax,ax / jmp; 'return a == b;' is one
   jmp shorter [76].
 - 'w[i] *= w[i]' keeps the lvalue address in SI (BX for the operand); 'w[i] = w[i] * w[i]' computes it twice [75].
 - Long products: the LEFT operand is evaluated and pushed first ('(long)research * bonus_pct') [77]. A long field
   OR'ed into another as 'a = b | a' (value first, address after) [76].
 - A char passed where a buffer is meant (cbw / push) only compiles with no prototypes in scope: drop <string.h>,
   declare the callee unprototyped [77]. A call with a different argument count -> unprototyped too [76].
 - Ownership from the relink (listd.py "no unmatched module for DGROUP lo..hi"): initialised data before this
   module's literals and after the previous module's literals is this module's (BCC emits literals last);
   unowned BSS just below this module's BSS is its too, declared in reverse address order [76]. Unreferenced holes
   inside the block: PROVISIONAL names [74].
 - Explicit 'register' on a local again stole SI from a param (Badges, Maybe_Buy, Global_Enchant_Relations): when
   the game keeps the param in SI, leave the local a plain auto [73 75 77].
 - Sparse switches (> ~4 non-dense cases) use BCC's search table (cx count / cs:[bx] compare loop / jmp cs:[bx+2n]);
   the case bodies still follow source order [77].

LIST D LESSONS (batches 79-82, 2026-10-20)
 - BCC's automatic register allocation (plain autos) favours the locals declared FIRST: City_Weapon_Grade's loop
   index only got DI (city param keeping SI) when 'int i;' was the first declaration; an explicit 'register' on it
   took SI from the param, and the same plain auto declared after the arrays got no register at all [82].
 - 'x *= 2' compiles to mov dx,2 / mov ax,si / imul dx / mov si,ax; 'x = x * 2' and 'x = 2 * x' become shl [82].
 - Switches over the 23 single terrain squares (0xa2..0xb8): write each terrain group as its own case group in
   source order (grassland, forest, mountain, desert, swamp, tundra, sorcery, nature, chaos, volcano 0xb3, hills
   0xab); BCC's cross-jumping turns identical bodies into jmps by itself. Decode the tables with raw words (a
   scratch reader of work/flat/WIZARDS_FLAT.EXE), not with the disassembly of the table bytes [82].
 - Return idioms: 'if (c) return 1; return 0;' has no dead jmp; 'if (c) return 1; else return 0;' leaves the dead
   jmp after the first return (Tile_Is_Corrupted). In an if / else-if chain a 'return' branch leaves a dead jmp
   to the end of the chain; a run of independent 'if (...) return n;' does not [82].
 - Comparison constants are literal: cmp 0x25a / jl is 't >= 602', cmp 0x1d8 / jle is 't > 0x1d8' [82].
 - Leaf functions put plain autos and even params in CX / DX (Build_Stacks' unit in DX) [81].
 - BSS blocks: define never-referenced holes and other modules' variables that fall inside the block here, in
   reverse address order; the fixup check reports "N different BSS bases" until the block is complete [80 81].
 - Spearmen / Swordsmen filter: 'if (a == 0 || b == 0) continue;' gives je-to-jmp / jne-over [80].
 - Line endings: GAME.H and some sources (WIZSTATS.C) are stored LF, most .C files CRLF - after a sed -i, restore
   the file's OWN convention (check git cat-file -p HEAD:path) [82].
 - ReMoM was not consulted until the whole rebuild was done (decided 2026-10-20) - resolve odd patterns by
   experiment [81].

LIST D LESSONS (batch 85, 83d2)
- A leaf with three register variables puts the third in CX: declared order i, type, node -> SI, DI, CX.
- `mov ax, field / cmp ax, K / je A / jmp B` with A right after is a one-case switch with a default:
  `switch (x) { case K: ... break; default: ... break; }` (the default's break is a jmp to the next instruction).

P1 LESSONS (2026-10-21)
- 'int f() { ...; g(); }' (no return statement, AX passes through) and 'return g();' compile DIFFERENTLY in BCC: keep
  the original's no-return form for wrappers whose callers use the value, with a comment.
- A far pointer seen as a long ('(long)Seg_To_Far_Ptr(seg) + 0x4a') reproduces the 32-bit add/adc, so a prototype
  can stay honest (void far *) and the cast carries the arithmetic.
- Changing a function's return type from void to int, or swapping a file's private struct copy for STRUCTS.H, does
  not move any byte; only declaration ORDER does (thunk order, _BSS order).

P2 LESSON (2026-10-21): compile every module in a FRESH DOSBox session. BCC runs in one session are not independent:
a run can generate different code depending on earlier runs (memory state), so a rename in one file changed another
file's register choice. match_build / match_all always did one module per session (that is what proved each module);
the full build now does too (tools/bcc_run.py run_many). And a verify step that stops early must FAIL, never compare
whatever EXE an earlier run left (tools/verify_fast.sh deletes the EXEs first and names failed steps).
